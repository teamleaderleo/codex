## Production hardening question

The summary currently joins every exact-cell live session ID. The manager has a normal soft process cap, but the store can temporarily exceed that cap while locked exited entries are being finalized. Therefore the summary has no independent hard cardinality bound.

This is not a demonstrated correctness failure, and normal model-history limits remain downstream. However, repository guidance prefers a hard bound for every model-visible fragment. Before the final production head is frozen, Agent 1 and Agent 3 should choose one of two explicit positions:

1. add a deterministic display cap with an omitted-count marker; or
2. retain the full point-in-time list and document that it remains subject to normal global history truncation.

Do not change process pruning or lifecycle policy to solve this presentation-bound question.
